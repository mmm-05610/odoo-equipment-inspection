# 验收范围

## 已完成的本地验收

- 用户按主管、检查员两套账号完成：方案、合格检查、异常确认转维修、维修返回检查、混合历史摘要、周期启停与到期生成、日历、活动、批量生成、权限边界、维修完成后的历史保留。
- 自动测试：周期开关调整后 86 项 post-install 全部通过；维修跳转修正后 24 项集成测试全部通过，新增了设备检查选专用表单、非设备检查保留上游视图的反例测试。
- 浏览器独立执行工厂数据 7 项场景；维修往返在隔离库和本地学习库分别连续执行两次，数据数量、状态和关联保持一致。
- 重置 HTTP 单元测试 5 项通过：读取不触发、跨站和无令牌拒绝、必须明确确认且不能选择数据库、并发与冷却限制，以及 HEAD 请求不触发重置。

初始 demo 测试只应在新生成的数据集上运行。经过用户操作后，原始状态分布改变是正常现象，不能把初始数量测试直接套在正在使用的演示库。

## 公开部署

2026-10-31 部署至 [公开演示](https://odoo.maomaokingdom.top/demo)，[GitHub 仓库](https://github.com/mmm-05610/odoo-equipment-inspection) 为 Public。

- HTTPS 域名证书验证通过；演示入口、账号说明与登录页面可访问。
- 检查员实际填写 P01 三项并提交合格；主管确认 P02 异常、创建维修、查看问题描述并返回设备检查专用表单。
- 线上检查日历能查看下月的只读计划。
- 上述操作使维修从 8 张变为 9 张；随后通过访客网页按钮真实执行重置，恢复 24 张检查、8 张维修，P01 重新待检查。
- 重置期间第二次请求返回 409，完成后的冷却请求返回 429；旧登录失效，两套公开账号可以重新登录。
- 模板与上一套备份库禁止连接，运行角色不是 PostgreSQL 超级用户，也不能建库或创建角色。通用数据库管理与外部 XML-RPC/JSON-RPC 入口被代理阻止，网页 RPC 正常使用。
- 管理员及其他演示人员默认密码已随机化，仅保留两套公开登录。自动 cron 和外发邮件关闭。
- 在独立的本地部署副本注入健康检查失败，切换失败后恢复上一套数据库与 filestore，验证先前写入标记仍在。本地学习库未参与这项故障注入。

公网直连 HTTPS GET/HEAD 与受限路由单独验证。为避开本机网络代理不稳定，完整浏览器业务与重置通过 SSH TCP 转发访问同一线上 Caddy，仍使用正式域名、HTTPS 证书校验和线上真实数据库；没有跳过 TLS 校验，也不是本机服务冒充线上。业务流程与修正权限配置后的重置为连续两段验收。

原始日志、截图与 JSON 留在维护者项目的 `.local-runtime/delivery/`，不公开数据库、日志中的内部信息或会话凭据。单元测试不替代真实恢复验证。

## 边界

未进行生产负载、长时间跨月调度、多公司网页全流程及完整安全审计。共享 demo 的公开重置会影响所有访客，操作前必须显示确认；演示账号不是管理员，真实数据不得录入。公开演示后台 cron 关闭。
